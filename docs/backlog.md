스레드는 요청이 오가는 자리고, 이 문서는 **무엇을 만들지 확정된 내용**을 담는다.

- 마지막 정리: 2026-08-24 (스레드 14개 / 요청 15건 기준)
- 사실 확인: 코드·DB 를 직접 조회해 적었다. 추측은 `조사` 에 반증까지 남긴다.

---

## 이 문서를 쓰는 방법

새 요청이 올라오면 아래 순서로 처리한다.

1. **스레드를 끝까지 읽는다.** 채널 본문에는 제목만 있고 실제 요구사항·이미지·링크는
   전부 스레드 안에 있다. 본문만 보면 껍데기만 보게 된다. (실제로 한 번 그랬다)
2. 해당 우선순위 절에 항목을 추가한다. **ID 는 다시 쓰지 않는다** — 끝난 항목도
   `## 완료` 로 옮길 뿐 번호를 재사용하지 않는다.
3. 조사해서 알아낸 것(이미 있는 기능인지, 외부 제약이 있는지)은 **`조사`** 에 적는다.
   같은 걸 두 번 파헤치지 않기 위한 것이다.
4. **제목은 디스코드 원문 그대로 쓴다.** `[신규] 주문 들어오면 알림 필요` 처럼
   말머리까지 옮긴다. 임의로 줄이거나 번호를 붙이면 어느 스레드 얘기인지
   서로 못 알아본다.
5. **반응 이모지를 확인한다.** 채널 본문 메시지에 달린 반응이 상태 표시로 쓰인다.
   ☑️ 는 처리됨, 🔄 는 진행 중. 스레드 본문만 읽으면 이미 끝난 일을 다시 파게 된다.
   (실제로 그럴 뻔했다 — 재현 안 되던 사진 버그에 이미 ☑️ 가 달려 있었다.)
6. 답이 필요한 건 **`미결`** 에 적고, 아래 [미결 질문](#미결-질문) 표에도 올린다.

### 항목 형식

```
### [말머리] 디스코드 스레드 제목 그대로
- 우선순위 / 상태(반응 이모지 포함) / 요청자 / 스레드 링크
- 요구  : 무엇을 만드는가 (요청자 표현 그대로 살릴 것)
- 조사  : 확인한 사실. 이미 있는 기능, 외부 제약, 반증된 추측
- 범위  : 손대야 하는 파일·계층, 작업 브랜치
- 완료조건 : 무엇이 되면 끝인가
- 미결  : 답이 있어야 진행되는 것
```

### 우선순위

요청자가 쓰는 말을 그대로 따른다: **긴급 / 우선 / 일반 / 기타**.
기한이 붙은 것(`일반(추석 이전 주까지)`)은 기한을 함께 적는다.

### DB 를 건드릴 때

마이그레이션이든 데이터 수정이든, **먼저 스냅샷을 뜬다.**

```
server/db/snapshot.sh "무엇을 왜 하는지"        # 운영
server/db/snapshot.sh "..." farmassi_dev        # dev
```

되돌릴 일이 생기면 `server/db/restore.sh <파일>`. 되돌리기 직전 상태도
자동으로 남으므로 잘못 되돌려도 다시 앞으로 올 수 있다.

### 브랜치

`ehyun`(server/, DB, 배포) · `ui`(src/ 화면) → `develop` → `main`.
한 항목이 양쪽에 걸치면 **범위** 에 둘 다 적고 커밋을 나눈다.

**요구 1 — 판매상태에 「별도 문의」 추가**

지금은 `on_sale / coming_soon / sold_out / hidden` 네 가지다
(`src/types/models.ts:14`, DB `products_sale_status_check`).
값을 하나 늘리는 것이므로 **프론트 타입 + DB 체크 제약 양쪽**을 고쳐야 한다.
주문 가능 여부(`isProductOrderable`)에서 어떻게 다룰지도 정해야 한다 —
「별도 문의」는 장바구니에 담기면 안 될 가능성이 높다.

**요구 2 — 택배 중량·부피를 우체국 요금 구간에 맞추기** ("둘 다 부탁")

여기가 처음 생각과 다르다. **컬럼은 이미 있다** —
`products.parcel_weight_kg`, `parcel_volume_cm` (둘 다 text).
그리고 이 값은 화면 표시용이 아니라 **우체국 창구소포 파일접수양식 엑셀**에
그대로 들어간다 (`src/lib/kpostParcelExcel.ts`, 시트명 `창구소포 파일접수양식`).
따라서 값을 마음대로 바꾸면 접수 파일이 거부될 수 있다.

현재 허용값과 요금표를 맞춰 보면:

| | 현재 허용값 | 요금표 구간(상한) | 차이 |
|---|---|---|---|
| 부피 | 80 / 100 / 120 / 160 | 80 / 100 / 120 / 160 | **이미 일치** |
| 중량 | 3 / 5 / 10 / 20 / 30 | 3 / 5 / **7** / 10 / **15** / 20 / **25** / 30 | **7·15·25 빠짐** |

즉 값 자체는 구간의 **상한**이고, 부피는 이미 맞다. 실제 문제는 둘이다.

1. **중량 구간 3개(7·15·25kg)가 빠져 있다.** 요금이 달라지는 구간인데 고를 수 없다.
2. **화면에 상한값만 보여서 뜻이 모호하다.** `5kg` 이 "정확히 5kg" 인지
   "3kg 초과 5kg 이하" 인지 알 수 없다. 요청자가 요금표 사진을 올리며
   "저 무한 표시가 ~일거임" 이라고 한 것이 이 지점이다.
   → 값은 그대로 두고 **라벨만 `3kg 이하` · `3~5kg` · `5~7kg` …** 로 바꾸면
   엑셀 양식을 건드리지 않고 해결된다.

요금(등기소포 창구접수 익일배달): 4,000 / 4,500 / 5,000 / 6,000 / 7,000 /
8,000 / 11,000 / 13,000원. **제주는 별도** — 제주→육지 익일배달은 6,500~15,500원이고
제주 익일배달 요금은 제주발에만 적용된다.
출처: https://parcel.epost.go.kr/parcel/use_guide/charge_1.jsp

- **범위** `src/lib/kpostParcelExcel.ts`(허용값·라벨), 상품 수정 화면,
  DB 체크 제약 `products_parcel_weight_kg_check`, `products_sale_status_check` / `ehyun` + `ui`

### 파이썬(FastAPI) 이관
- **상태** 코드 완료, 전환 남음 · 대조 102건 일치
