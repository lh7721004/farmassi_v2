# 백로그

디스코드 **#수정방**(`stable fusion` 서버)에 올라오는 요청을 정리해 둔 곳이다.
스레드는 요청이 오가는 자리고, 이 문서는 **무엇을 만들지 확정된 내용**을 담는다.

- 원문: https://discord.com/channels/1458046783795236947/1541094943857320058
- 마지막 정리: 2026-08-24 (스레드 18개 / 요청 19건 기준)
- 사실 확인: 코드·DB 를 직접 조회해 적었다. 추측은 `조사` 에 반증까지 남긴다.

---

## 이 문서를 쓰는 방법

새 요청이 올라오면 아래 순서로 처리한다.

1. **스레드를 끝까지 읽는다.** 채널 본문에는 제목만 있고 실제 요구사항·이미지·링크는
   전부 스레드 안에 있다. 본문만 보면 껍데기만 보게 된다. (실제로 한 번 그랬다)
2. 해당 우선순위 절에 항목을 추가한다. **ID 는 다시 쓰지 않는다** — 끝난 항목도
   `## 완료` 로 옮길 뿐 번호를 재사용하지 않는다.
3. 조사해서 알아낸 것(이미 있는 기능인지, 외부 제약이 있는지)은 **`조사`** 에 적는다.
   같은 걸 두 번 파헤치지 않기 위한 것이다.
4. **제목은 디스코드 원문 그대로 쓴다.** `[신규] 주문 들어오면 알림 필요` 처럼
   말머리까지 옮긴다. 임의로 줄이거나 번호를 붙이면 어느 스레드 얘기인지
   서로 못 알아본다.
5. **반응 이모지를 확인한다.** 채널 본문 메시지에 달린 반응이 상태 표시로 쓰인다.
   ☑️ 는 처리됨, 🔄 는 진행 중. 스레드 본문만 읽으면 이미 끝난 일을 다시 파게 된다.
   (실제로 그럴 뻔했다 — 재현 안 되던 사진 버그에 이미 ☑️ 가 달려 있었다.)
6. 답이 필요한 건 **`미결`** 에 적고, 아래 [미결 질문](#미결-질문) 표에도 올린다.

### 항목 형식

```
### [말머리] 디스코드 스레드 제목 그대로
- 우선순위 / 상태(반응 이모지 포함) / 요청자 / 스레드 링크
- 요구  : 무엇을 만드는가 (요청자 표현 그대로 살릴 것)
- 조사  : 확인한 사실. 이미 있는 기능, 외부 제약, 반증된 추측
- 범위  : 손대야 하는 파일·계층, 작업 브랜치
- 완료조건 : 무엇이 되면 끝인가
- 미결  : 답이 있어야 진행되는 것
```

### 우선순위

요청자가 쓰는 말을 그대로 따른다: **긴급 / 우선 / 일반 / 기타**.
기한이 붙은 것(`일반(추석 이전 주까지)`)은 기한을 함께 적는다.

### DB 를 건드릴 때

마이그레이션이든 데이터 수정이든, **먼저 스냅샷을 뜬다.**

```
server/db/snapshot.sh "무엇을 왜 하는지"        # 운영
server/db/snapshot.sh "..." farmassi_dev        # dev
```

되돌릴 일이 생기면 `server/db/restore.sh <파일>`. 되돌리기 직전 상태도
자동으로 남으므로 잘못 되돌려도 다시 앞으로 올 수 있다.

### 브랜치

`ehyun`(server/, DB, 배포) · `ui`(src/ 화면) → `develop` → `main`.
한 항목이 양쪽에 걸치면 **범위** 에 둘 다 적고 커밋을 나눈다.

## 확인 필요

### dev 서버 뱅크다 환경변수 (수정방 밖)
- **상태** 의도적으로 비워 둠 (변경하려면 결정 필요)
- **사실** `server/.env.dev` 에서 `BANKDA_ACCESS_TOKEN`, `SMTP_PASSWORD` 가 비어 있고
  `SCRAPE_CHECK_MINUTES=0` 이다.
- **비워 둔 이유**
  1. 뱅크다 계정이 하나뿐이다. dev 에서 토큰을 쓰면 실제 가맹점·계좌가 만들어진다.
  2. 거래내역 조회 5분 제한을 운영과 나눠 쓰게 된다.
  3. **dev DB 는 개인정보를 마스킹한 복사본인데, 뱅크다 조회는 실제 입금자 실명을
     가져온다.** 게다가 dev 계좌번호가 가짜라 어느 농가와도 안 맞아
     `farm_id = null` 로 실명만 쌓인다. 마스킹한 의미가 사라진다.
- **선택지**
  - A. 그대로 (지금)
  - B. 토큰만 넣고 스케줄러는 끈 채로 — 계좌 상태 조회는 가능, 자동 수집 없음.
    단 OTT 발급 버튼은 누르면 **실제** 가맹점이 생긴다.
  - C. 전부 켜기 — 3번 때문에 권하지 않음
- **미결** A / B / C

    올 수 있어야 한다.
